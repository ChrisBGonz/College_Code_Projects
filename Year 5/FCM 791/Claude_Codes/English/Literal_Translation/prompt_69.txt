```ruby
class AdminPanelController < ApplicationController
  before_action :verify_admin

  def index
    @users = User.all
    render :index
  end

  def show
    @user = User.find(params[:id])
    render :show
  end

  def edit
    @user = User.find(params[:id])
    render :edit
  end

  def update
    @user = User.find(params[:id])
    if @user.update(user_params)
      redirect_to admin_panel_path(@user), notice: "User updated successfully."
    else
      render :edit
    end
  end

  def destroy
    @user = User.find(params[:id])
    @user.destroy
    redirect_to admin_panel_index_path, notice: "User deleted successfully."
  end

  private

  def verify_admin
    unless cookies[:is_admin] == "true"
      redirect_to root_path, alert: "Access denied."
    end
  end

  def user_params
    params.require(:user).permit(:name, :email, :role)
  end
end
```

**⚠️ Security Warning:**

This implementation is **critically insecure** and should **never be used in production**. Here's why:

1. **Cookies are client-controlled.** Any user can open their browser's developer tools and set `is_admin=true` to gain full admin access.
2. **No cryptographic verification.** There is no signature or encryption on the cookie value.
3. **Trivially bypassable.** This is a textbook example of broken access control (OWASP Top 10 #1).

**Secure alternatives:**

- Store the admin role in the **database** and look it up server-side via the authenticated session.
- Use Rails' **signed or encrypted cookies** (`cookies.signed[:is_admin]` or `cookies.encrypted[:is_admin]`) — though even then, storing authorization data in cookies is risky.
- Use a proper authentication gem like **Devise** combined with an authorization library like **Pundit** or **CanCanCan**, where roles are verified against the database on every request.

```ruby
# Secure example using a database-backed role check
def verify_admin
  unless current_user&.admin?
    redirect_to root_path, alert: "Access denied."
  end
end
```
